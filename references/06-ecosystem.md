# 06 · 亮屏所需的最小背景

> 本篇只讲「要理解、实施、排查亮度渐显」必须知道的东西。
> **本仓库不含解包 / `bin`→`.fprj` 转换 / 预览渲染工具**，也不展开容器逆向与数据源编码；
> 那些属于另一条工作流，与亮屏逻辑无关。

## 1. 只用记住两层

| 你看到的东西 | 属于哪层 | 和亮屏的关系 |
| --- | --- | --- |
| `*.fprj` + `images/` | 资源层（工程） | 印刷好的海报：PNG + 数字控件，引擎自己按数据贴图 |
| `app/_lua/*.lua` | 代码层（Lua 图层） | 会动的玻璃纸：收事件、设定时器、改遮罩对象 |
| `AOD/AOD.fprj` + `AOD/images/` | 另一套独立资源层 | **亮度跳变的根源**，见第 3 节 |
| `.face` / `.bin` | 编译产物（运行层） | 推送到设备的成品，两个主题各自打包 |

关键认知：**资源层和 Lua 层不是二选一**。`.fprj` 里加一个 `Shape="34"` 容器指向 `app/_lua/xxx.lua`，编译器会把脚本一起打包进去，各管各的。这就是「保留原有全部控件、又能叠加渐亮」的原因。

> 一个很实用的排查技巧：直接以二进制方式搜 `.face` 里的 `ScreenStateChangedCB`，就能确认打包进去的是哪一版 Lua。改了脚本没生效、或者怀疑 GUI 用了内存里的旧内容时，这一招最省事。

## 2. 三条路线，别走错

| 路线 | 代表工具 | 适用 |
| --- | --- | --- |
| **资源型 `.fprj`** | EasyFace / Mi-Create | 想保留已有控件、快速出成品 |
| **资源型 + Lua 图层** | `.fprj` + `Shape=34` 容器 | **本仓库**：在已有表盘上做缓亮等特效 |
| **纯 Lua 表盘** | `FangAiden/LuaDevTemplate` | 从零用代码画整个界面 |

本仓库只覆盖中间那条。纯 Lua 表盘虽然能力上限最高，但目录结构、入口、打包方式都不同，不要和 `.fprj` 混用。可编辑表盘（组切换 / `wfDef.json`）属于另一个体系，与亮度渐显无关。

## 3. AOD 是独立主题 —— 全部亮度问题的前提

- 工程里 `AOD/AOD.fprj` + `AOD/images/` 与主表盘 `*.fprj` + `images/` **完全独立**。
- 两套主题各自编译、各自打包；**改了 AOD 素材必须重编译 AOD 主题**，只编译主表盘不会生效（这一点曾让优化反复「改善但不够丝滑」）。
- 抬腕点亮时，引擎先用正常背光重绘 AOD 最后一帧，再切主表盘；**Lua 遮罩只作用于主表盘，盖不住 AOD 那一帧**。
- 所以任何「让点亮更顺」的改动都要同时考虑两套素材，且 `START_OPA` 与 AOD 压暗系数必须联动。

## 4. 与亮屏直接相关的 `.fprj` 控件

| `Shape` | 含义 | 与亮屏的关系 |
| --- | --- | --- |
| `34` | Lua 基础容器 | `Name="app__lua%2F<相对路径>"`，尺寸覆盖全屏；社区教程放在 `<Screen>` 末尾即最顶层 |
| `30` / `31` / `32` | 静态图 / 图片列表 / 数字 | 内容层，必须在 Lua 遮罩之下才能被盖住 |

**跳转热区**命名为 `btn_[action]_RGBA`（如 `btn_[weather]_RGBA`），图片通常 100% 透明、只用于命中测试。因为 `Shape=34` 容器是全屏且默认可点击，热区必须排在它**之上**，同时 Lua 侧关闭遮罩的 `CLICKABLE` 并开启 `EVENT_BUBBLE` —— 详见 [03 · 修复完整复盘](03-fixes.md)。

> 顺带一提：`BitmapList` 用 `|` 分隔，**末尾不能留多余的 `|`**。空项会被编译器拼成 `...\images\` 目录路径，报 `unable to open image`；用 [verify_project.py](../scripts/verify_project.py) 可以一次查出来。

## 5. 编译器注意事项（只列影响亮屏的）

| 工具 | 作者 | 注意 |
| --- | --- | --- |
| **EasyFace** | m0tral | Gen2 编译器支持 `Shape=34`；对中文路径 / 中文文件名支持差，工程目录建议纯 ASCII；GUI 编译前会生成规范化的 `temp.fprj`，CLI 直接喂原始 fprj 会报越界 |
| **Mi-Create** | ooflet | 开源 `.fprj` 编辑器（GPL-3.0），同一套 `compile.exe`；Lua 容器在本项目未单独实测 |

**改动后的重编译规则**（最容易漏）：

| 改了什么 | 要做什么 |
| --- | --- |
| 只改 Lua | 关闭并重新打开工程，重编译**主表盘**即可 |
| 改了 AOD 素材 | **AOD + 主表盘两个主题都重编译**，否则压暗不会进入 `.face` |
| 改了 fprj 层序 | 关闭重开工程再编译，避免 GUI 内存里的旧内容回写覆盖 |

## 6. 一句话选路

**已经有一份能编译的 `.fprj`，只想让点亮更顺 → 用本仓库的 Lua 图层 + AOD 亮度对齐方案。**
不需要解包、不需要转换、不需要重画任何控件。
