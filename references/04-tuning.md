# 04 · 参数调优与排错

## 1. 唯一必须成对改的公式

```
START_OPA = 255 × (1 − AOD 亮度系数)
AOD 亮度系数 = 1 − START_OPA / 255
```

| `START_OPA` | 对应系数 | 效果 |
| --- | --- | --- |
| 97 | **0.62** | 默认，真机验证的稳定组合 |
| 64 | 0.75 | AOD 常显更亮、渐显更浅 |
| 150 | 0.41 | 渐显最明显，但 AOD 常显偏暗 |
| 0 | 1.00 | 不做渐显（AOD 素材保持原始亮度） |

**改 `START_OPA` 必须同时改 AOD 素材**，且两个主题都要重编译：

```bash
python scripts/dim_aod_assets.py <工程> --factor 0.62 --sync
#                                       ^^^^^^^ 自动把 START_OPA 同步成 97
```

单独改任一个，都会重新引入「AOD 亮帧 → 主表盘暗帧」的跳变。

## 2. 可以单独调的参数

这几个只影响渐显的平滑度，不动亮度配对，可以放心试：

| 参数 | 当前 | 调大 | 调小 |
| --- | --- | --- | --- |
| `FRAMES` | 32 | 台阶更小、更柔，但更慢 | 台阶更大、更快，可能看出阶梯 |
| `PERIOD` | 17 ms | 每帧更容易被手环刷新跟上，但整体变慢 | 更快，但可能掉帧 |
| `MIN_OPA` | 1 | 收尾跳变变大 | 无意义（已是最小） |

`step = ceil(START_OPA / FRAMES)`，实际帧数由 step 决定，不一定等于 `FRAMES`：

| `FRAMES` | `step` | 可见帧 | 时长 | 末帧跳变 | 评价 |
| --- | --- | --- | --- | --- | --- |
| 24（v6 原值） | 5 | 19 | 323 ms | `7→0`，2.7% | 收尾有一下「突然亮」 |
| **32（v6.1）** | **4** | **25** | **425 ms** | `1→0`，0.4% | **当前值，推荐** |
| 48 | 3 | 33 | 561 ms | `1→0` | 更柔但偏慢 |
| 97 | 1 | 97 | 1649 ms | 0 | 极致细腻，通常太拖 |

回退到「当前好用状态」：`FRAMES=24`、`MIN_OPA=6`。

## 3. 症状 → 原因 → 处理

| 症状 | 最可能的原因 | 处理 |
| --- | --- | --- |
| **完全没有动画** | 状态分流把 AOD 点亮改成直接全亮；或脚本用了被裁剪的 `string.*` 导致整体不生效 | 回到「所有点亮都渐变」的逻辑；移除 `string.upper/find` 等调用 |
| **渐显几乎看不见** | 遮罩太淡（如 `START_LIT=55`）且 AOD 素材是全亮 | 回到 `START_OPA=97` + AOD ×0.62 的成对组合 |
| **点亮先闪一帧黑** | 首帧遮罩还没就位（`bg_opa` 要等 Timer 第一次回调才设） | 先 `scr:set` 再 `clear_flag(HIDDEN)`；Timer 创建后立即 `pause()` |
| **先闪一下最亮、再变暗渐显** | AOD 帧比主表盘首帧亮（结构性下凹） | 压暗 AOD 素材并配对 `START_OPA`，**两个主题都重新编译** |
| **只有收尾「突然亮一下」** | `MIN_OPA=6` 导致末帧 `7→0` | `MIN_OPA=1` |
| **能看出一阶一阶的台阶** | `step` 太大 | `FRAMES=48`（step=3）；必要时把 step 改成浮点并在 `set` 时取整 |
| **改了 Lua 但真机没变化** | 用了旧 `output/*.face`；或 GUI 内存里的旧工程回写覆盖 | 关闭并重新打开 `.fprj` 再编译；推送前核对产物时间戳 |
| **压暗 AOD 后观感没改善** | AOD 主题没重新编译，压暗没进运行时 | 重编译 AOD + 主表盘两个主题 |
| **叠加 Lua 后所有跳转失效** | 全屏遮罩吃掉了触摸事件 | 组合修复：Lua 侧 `CLICKABLE`/`EVENT_BUBBLE`/`park_veil()` + 工程侧热区排到 Lua 容器之上 |
| **AOD 常显太暗** | 系数 0.62 偏低 | `--factor 0.75 --sync`（`START_OPA` 自动变 64），衔接仍对齐 |
| **编译报 `images\` 路径错误** | `BitmapList` 末尾多余 `\|` 生成空文件名 | 按字节去掉空项（`verify_project.py` 可自动查出） |
| **EasyFace 打不开工程** | 中文目录 / 文件名 | 改成纯 ASCII 路径 |

## 4. 编译与推送检查清单

改动之后按这个顺序确认，能省掉大半返工：

1. **判断改动范围**
   - 只改 Lua → 只需重编译主表盘；
   - 改了 AOD 素材或 `AOD.fprj` → **两个主题都要重编译**。
2. **关闭并重新打开 `.fprj`**，别用 GUI 的旧会话（否则内存中的旧内容会回写覆盖磁盘修复）。
3. **编译后核对产物**：在 `.face` 里搜 `ScreenStateChangedCB` / `START_OPA` 确认打包的是新脚本；量一下 `AOD/images` 里白色数字帧峰值（158 = 已压暗，255 = 原始）。
4. **只用本次新生成的 `.face`** 推送，旧 `output/` 里的产物全部作废。
5. **真机验证三件事**：点亮无亮度回落、渐显可见且平滑、5 个跳转仍正常。

用脚本做静态自检：

```bash
python scripts/verify_project.py <工程>
# 原始 AOD 素材在工程外时：
python scripts/verify_project.py <工程> --source <原始素材目录>
```

它会检查 ASCII 路径、两份 fprj 的 XML 合法性、`Bitmap`/`BitmapList` 空项与缺失文件、Lua 容器与热区层序、点击修复三要素、AOD 素材压暗系数与 `START_OPA` 是否配对、PNG 完整性。AOD 主题没有 Lua 容器属正常状态，不会误报。

## 5. 天花板：什么做不到

这套「资源型表盘 + Lua 黑遮罩」架构有三个无法绕过的限制：

1. **遮罩盖不住引擎绘制的 AOD 帧。** 想完全消除亮度不连续，只能让两帧像素亮度相等（本方案），或者让 AOD 与渐显二选一。
2. **遮罩只能变暗，不能提亮。** 做不到「从比 AOD 更亮的起点渐入」，也做不到物理背光渐变。
3. **没有背光 / 亮度 API。** `screen` 模块为空表，`lvgl.disp` 只有背景属性；`load_scr(anim="fade_on")` 是 Lua 自己切屏用的，插不进引擎的 AOD → 主表盘切换。

因此：

> **要动画、又要零跳变，唯一出路是工程层把 AOD 压到与主表盘首帧同亮度。**
> 若固件把 AOD 也报成 `OFF` 导致状态判断异常，可把 `OFF` 从「熄屏」集合移到「息屏」集合（代价是熄屏点亮也不再渐亮）。

## 6. 尚未实施、但可行的进一步优化

这两项能再平滑一档，但会动 Timer 逻辑，建议先保留 v6.1 作为一键回退：

- 把 `step` 从整数改成浮点 `START_OPA / FRAMES`，在 `scr:set` 时取整 → 彻底消除量化台阶、精确用满帧数。
- 用 `lvgl.Anim` 的 `ease_out` 路径（参考 `LeeKLong/Lua_MiBand9Pro`），让衰减先快后慢，比线性更接近自然亮屏。

前提是目标固件确实支持 `lvgl.Anim`；不支持时退回 Timer 方案即可。
